## Section 13 — Strategic & holistic recommendations

> **Philosophy preamble — read before changing any 13.x item.**
>
> The PM is **not** a single global policy engine. It is a confederation of highly specialized local winners — one per (symbol × timeframe × regime × strategy) — each with strong contextual autonomy. Specialization, local optimization, and per-context decision-making are core *strengths*, not weaknesses to be flattened by an umbrella governance layer.
>
> Section 13 distinguishes three responsibilities, and every item below must respect them:
>
> 1. **Strategy tournament** — finds the best strategy + hyperparameters for each exact (symbol × TF × regime) context. Already shipped via Phases A–E.
> 2. **Local governance tournament** — finds the best *order-management / governance model* for that same exact context, by simulating candidate governance models against one another per-(symbol × TF × regime × strategy) and selecting the winner *locally* (§13.6). Governance is not a global setting; it competes in the same tournament style as the strategy itself.
> 3. **PM as execution & orchestration infrastructure** — the unifying role of the PM-as-engine is technical: order flow, broker calls, MT5 plumbing, decision throttle, the live loop. It is *not* a global policy engine that overrides what local winners decided.
>
> **Cycle-cadence invariants that constrain Section 13:**
> - The PM operates on a **fixed two-week retraining cycle**. That cycle *is* the freshness mechanism. Section 13 must not introduce mid-cycle fail-closed deactivation or auto-shutdown logic that overrides live trading inside the active cycle. Reviews happen as a structured **weekly review** within or at the end of the live period — they surface information for the operator, they do not pull triggers.
> - Capital should **stay productively deployed** wherever local winners justify it. Section 13 must not introduce umbrella-level lockouts or account-wide concurrent-risk caps that constrain the PM's productive capacity beyond what individual local winners already enforce.
> - The validation → live transition must remain **prompt** so the tuned parameter state matches the market the system actually trades. Section 13 must not insert a delay layer (e.g., a walk-forward promotion ladder running between validation and live) that ages winners before they reach the market.

## Cross-cutting principles enforced on every change

1. **No regression in code quality.** A defensive comment is added only when the *why* is non-obvious; no narrative comments.
2. **No silent fallbacks.** Every behavioral fork is logged at INFO/WARN with reason code.
3. **No orphaned outputs.** Every newly written file or persisted field has a reader exercised by tests.
4. **No new config-vs-code drift.** Every new `PipelineConfig` field has a committed `config.json` entry ≤ code default, or is opt-in/None-defaulted.
5. **Atomic state transitions.** Any new persisted state (decision throttle, governance block, cooldowns) uses the established atomic-write pattern.
6. **Documentation sync in same commit.** README / SETTINGS_REFERENCE / CHANGELOG updated alongside operator-visible changes.

## Rollout discipline

- **Tightening / correctness fixes** (Phase A, B, C, D, parts of E) ship as soon as tests pass — `TECHNICAL_DIRECTION §8` change-control category "Correctness fix" / "Tightening": no paper-week required, deploy immediately.
- **Loosening / new feature** items (Phase E new strategies, §13.3 observatory, §13.6 governance-tournament live arms) require the paper-week observation gate per `TECHNICAL_DIRECTION §8`.
- **Structural items** (§13.6 governance-tournament backtest layer, §13.7 TradeIntent) ship behind explicit flags with the three-stage validation ladder (offline replay → shadow live → controlled A/B). The §13.6 A/B compares the per-context governance winner against the no-governance baseline *for that same context* — never one model against another globally.
- **Anti-umbrella guardrail.** Any 13.x item that would auto-deactivate, derate, force-close, or block live trading mid-cycle on freshness or aggregate-risk grounds requires explicit written justification against the philosophy preamble. The 2-week retraining cycle is the freshness mechanism; weekly review is the human-in-the-loop surface; local winners retain sizing authority.
