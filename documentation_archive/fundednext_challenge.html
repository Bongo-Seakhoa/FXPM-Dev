FXPM FundedNext 5K Challenge Preparation

This document records the PM's 5K FundedNext challenge profile using pm_configs_high_risk.json as the strategy winner ledger once the current optimization is complete. The strategy selection surface should remain the optimized FXPM surface; the funded account must receive a funded-challenge execution profile that preserves PM freedom while reducing only the risk settings that no longer fit a 5K account.

Operating principle: preserve strategy quality and profitability intent first, then adapt live sizing, same-symbol exposure, governance activation, and broker feasibility to the 5K account without turning the PM into a timid or over-filtered system.

Challenge Posture

The high-risk ledger is acceptable as a selection source. The change for FundedNext should be the account expression layer: smaller primary risk, a 1% hard trade cap, equity-aware sizing, active local governance, and no artificial conservative launch mode.

Governance Reality

Implemented, selected per context, currently shadowed live

The optimization pipeline does select a governance policy per exact winner context and persists it onto the artifact. The live runtime dispatches that artifact policy per open trade after resolving symbol, timeframe, regime, and ticket state.

In the current interim ledger snapshot, tradeable regime slots show 488 control_fixed, 30 atr_trail_capped, 26 breakeven_1r, and 19 pure_atr. That means governance is real, but most contexts are still selecting the baseline fixed-control policy.

Live Activation Meaning

local_governance_live_mode = "on"

In shadow, governance computes would-be SL/TP changes and stores shadow state, but it does not call broker modification. In on, non-control policies can call modify_position to tighten stops or release TP according to the selected local policy.

For the funded challenge intent, governance is now promoted to on, while risk scalars remain in shadow unless there is a deliberate decision to let them reduce live sizing.

Go Conditions
  • pm_configs_high_risk.json has completed the expected symbol universe and no stale pre-boundary winners remain.

No-Go Conditions
  • The challenge is not actually Stellar 2-Step and the rule envelope has not been recalculated.
  • The optimizer file is still partial, stale, or contains expired/pre-boundary configs intended to be replaced by the current run.
  • The PM still has 2% per-trade live risk, 3% max trade risk, or 4% same-symbol combined risk when the funded account is meant to run the 5K profile.
  • Governance is expected to be active, but local_governance_live_mode is still left in shadow.
  • Broker symbol mapping or instrument specs are assumed from the old environment instead of pulled from FundedNext MT5.
  • The operator believes there is a PM-wide portfolio cap where the code only implements same-symbol caps and report-only observability.

First-week stance: let the PM trade naturally under the funded profile rather than a special conservative mode. The aim is to let the optimized ledger express edge while keeping the per-trade and same-symbol sizing settings matched to the 5K account.
